# Handoff: RIDEMALL 车机端商城（Android 车机原生实现）

## Overview
RIDEMALL 是一个**车载中控大屏（车机端）购物商城 demo**。横屏 16:9、固定分辨率 **1920×1080**、不可旋转、沉浸式（无系统状态栏）。整体结构为「左侧常驻竖向导航 + 右侧内容区」，共 8 个界面 + 若干交互状态。内部演示用，**不接真实支付**（扫码页点击任意位置即视为支付成功）。

## About the Design Files
本包内的 `design_src/` 是**用 HTML/CSS/React 做的设计参考稿**——它表达的是「最终视觉效果 + 交互行为」，**不是可直接搬运的生产代码**。任务是把这些设计在**安卓车机原生工程**里**重新实现**，使用该工程已有的架构与组件库。

若当前还没有现成工程：建议用 **Kotlin + Jetpack Compose** 新建。理由：本设计大量使用自定义深色主题、渐变、缩放适配、状态驱动的路由切换，Compose 的声明式 + `remember/State` 模型与设计稿的 React 状态机几乎一一对应，迁移成本最低。下文的「State Management」「Interactions」均按 Compose 思路给出，但你可自行折算到 View 体系。

> 车机注意：锁定横屏（`android:screenOrientation="landscape"`）、全屏沉浸（隐藏状态栏/导航栏，`WindowInsetsControllerCompat` + `IMMERSIVE_STICKY`）、保持常亮（`FLAG_KEEP_SCREEN_ON`）。设计基于 1920×1080；其它分辨率用等比缩放/约束布局适配，不要改变 16:9 构图比例。

## Fidelity
**High-fidelity（hifi）。** 颜色、字号、间距、圆角、状态都已确定，请按下文 token 像素级还原。唯一的占位部分是**商品图/Banner 图**——设计稿用条纹占位图，生产环境替换为真实图片即可（见 Assets）。

## Screens / Views

> 路由是单 Activity / 单 Composable 树内的状态切换，不是多页面跳转。一个 `screen` 状态决定右侧渲染哪个界面；扫码/成功/网络异常是**盖在最上层的全屏覆盖层**（连左侧导航一起盖住）。

### 通用骨架
- 根容器固定 1920×1080，整体等比缩放到屏幕（letterbox 黑边，居中）。
- 左侧 `NavRail`（常驻，覆盖层出现时被盖住）：顶部品牌区（青色圆角方块 Logo + "RIDE**MALL**"，MALL 为青色）→ 6 个顶部项 → 分隔线 → 底部「订单」项。
- 导航 7 项，从上到下固定顺序：**推荐 / 车载用品 / 加油充电 / 户外旅行 / 3C数码 / 品质生活 /（最底）订单**。
- 选中态：项背景 = accent-soft，1px accent-line 描边，文字 text-1 加粗，图标变 accent，**左侧贴边一条 4×30px 青色竖条**（带 glow）。未选中：文字 text-2，hover 时背景 `rgba(255,255,255,.035)`。

### 1. 推荐页（默认首页）
- **Purpose**：进入即见，展示 Banner 轮播 + 推荐商品流。
- **Layout**：内容区可纵向滚动。顶部 Banner 轮播（共 **4 张**，每 **3 秒**自动切换，下方 4 个圆点指示当前张，圆点可点击跳转）；下方「为你推荐」区块标题（左侧 5×30 青色竖条）+ 两列商品网格（约 10–12 个，可下滚）。
- **首页底色点缀**：内容区叠一层极淡的青色径向光晕（右上为主、左下更弱），分量很轻。
- **Banner（布局 A，已选定）**：宽幅横幅，高 384px，圆角 14。底图为商品图，左侧叠 `linear-gradient(105deg, 黑95% → 透明)` 让文字可读。文字块（左对齐，最大宽 62%）：kicker（青色、大写、字间距 3px）→ 标题（可两行，`white-space:pre-line`）→ 描述（text-2）→ 价格（Oxanium，`¥` 青色）。点击 Banner 进入对应商品详情。
- **商品卡**：竖向卡片 = 顶部图（占位）+ body（名称 1–2 行 → 一行内左价格右「查看 ›」弱文字）。hover 上浮 3px + 青色描边 + 阴影。点击进详情。
- **示例 Banner 文案**：见 `design_src/data.js` 的 `slides`。

### 2. 分类商品页
- **Purpose**：点左导航任一分类，右侧出该类商品网格。无独立分类页，分类即导航。
- **Layout**：顶部页面标题 = 分类名（如「车载用品」）+ 右侧弱文字「N 件商品」；下方两列商品网格（同推荐页卡片样式），可下滚。
- **空态**：该类无商品时，居中显示：一个 110×110 虚线圆角框（内含图标）+ text-2 文字「该分类暂无商品」。

### 3. 商品详情页
- **Purpose**：看图、看信息、下单。
- **Layout**：顶部「‹ 返回」胶囊按钮。下方左右两栏：
  - 左（760px）：大主图（高 540，圆角 14，1px line 描边）+ 下方一排 **3 张缩略图**（154×120，点击切换主图，选中态青色描边 + 青色外发光）。
  - 右（1fr）：商品名（大）→ 价格（超大，青色，`¥` 略小）→ **3 个固定标签**（胶囊，accent-soft 底 + accent-line 描边 + 青字 + ✓ 勾，文案固定：`7天无理由` / `包邮` / `自营`）→「商品描述」小标签 → 描述正文 → 醒目的「**下单**」大按钮（青色填充，块宽）。
- 点「下单」→ 确认订单页。

### 4. 确认订单页
- **Layout**：顶部「‹ 返回」+ 页面标题「确认订单」。下方（最大宽 1080）两张面板卡：
  - **卡一 收货信息**（只展示、不可编辑）：卡头「收货信息」+ 右上灰色徽章「演示 · 固定地址」；正文一行：`张三`（加粗）`138****8888`（Oxanium）`上海市浦东新区 ×× 路 ×× 号`（text-2）。
  - **卡二 订单详情**：卡头「订单详情」；一条行项目 = 96×96 缩略图 + 商品名 + 右侧价格 `¥39.00` + 数量 `×1`；下方分隔线后右对齐「合计 **¥39.00**」（合计金额青色 Oxanium）。
- 底部右对齐醒目按钮「**去支付 ¥39.00**」（金额用 Oxanium，按钮 `white-space:nowrap`）。→ 扫码支付页。

### 5. 二维码支付（全屏覆盖，盖住左导航）
- **Layout**：全屏深色（中心一圈径向微光）。垂直居中：标题「请扫码支付 **¥39.00**」（金额青色，单行不换行）→ 白底圆角(22)容器内一张二维码（约 250×250，深色码点 `#0A0C0F`）→ 倒计时「支付剩余时间 **02:59**」（标签 text-2，时钟 Oxanium 青色 46px）→ 小字提示「点击屏幕任意位置 = **支付成功**（演示用）」。
- **倒计时**：从 02:59 每秒递减。**≤30 秒**时钟变红（warn-red）。
- **超时态（归零）**：替换为——amber 警告环 + 「支付超时」+「二维码已失效，请重新发起支付」+ 两个按钮：「重新支付」（青色描边 ghost，重置倒计时）/「返回订单」（回确认订单页）。
  > ⚠️ **【下游集成批注 · D-001,2026-05-29,以此为准】本超时态不实现。** 经用户裁决(见 [ADR-0004 §B](../../docs/adr/0004-car-ui-ia-redesign.md) + [drift-log D-001](../../docs/drift-log.md)),倒计时归零后**仅显示「支付超时」提示,系统不处理**——不显示「二维码已失效」,不做「重新支付 / 返回订单」两个按钮;**用户点屏任意处仍可支付成功**(共识锚点 F5)。设计稿此段为设计期方案,已被推翻,实现时忽略。
- **支付成功触发**：点击页面任意位置即视为成功 → 生成一笔订单（见 State）→ 成功页。

### 6. 支付成功（全屏覆盖）
- **Layout**：垂直居中：一个**对勾成功环**（168px accent-soft 圆 + 内嵌 118px 青色实心圆 + accent-ink 色 ✓，入场 `pop` 弹性缩放动画 0.5s）+ 大标题「支付成功」+ 小字「1.5 秒后自动返回推荐页」。
- **行为**：**1.5 秒**后自动跳回推荐页（导航高亮回到「推荐」）。

### 7. 订单历史页（导航「订单」）
- **Layout**：页面标题「我的订单」+ 右侧「N 笔」。下方（最大宽 1140）订单卡列表，**按时间倒序**。每张卡：
  - 顶部行：左侧下单时间（Oxanium）+ 右侧状态徽章「✓ 已支付」（青色胶囊，accent-soft 底 + accent-line 描边）。
  - 中部行项目：缩略图 + 商品名 + 价格 + `×数量`。
  - 底部（分隔线后）弱文字收货行：「收货 张三 138****8888 上海市浦东新区××路××号」。
  - 点击卡片可进对应商品详情。
- **空态**：无订单时居中显示虚线圆角框（含 receipt 图标）+「暂无订单」。
- 初始 seed 3 笔历史订单；每次支付成功新增一笔（插到最前）。

### 8. 网络异常（全屏覆盖，盖住左导航）
- **Layout**：垂直居中：amber 警告环（150px，`rgba(255,168,76,.1)` 底 + `.4` 描边 + amber ⚠ 图标）+ 大标题「网络异常」+ 小字「请检查网络后重试」+「点击重试」按钮（青色描边 ghost）。
- 在设计里由开关触发用于演示；生产中应在真实网络/接口失败时展示，「点击重试」重新发起当前请求。

## Interactions & Behavior
- **导航点击**：推荐 → 首页；订单 → 订单历史；其余 → 对应分类页。当前项高亮。进入「详情/确认」时导航高亮保持在来源分类。
- **Banner 轮播**：3 秒自动轮播（可配 2/3/5 秒），圆点点击跳转，切换为 0.7s 透明度淡入淡出。
- **商品卡 hover**：上浮 3px + 青色描边 + 阴影，过渡 0.18s。
- **缩略图切换**：点击即换主图，选中态描边高亮。
- **下单流**：详情「下单」→ 确认订单 → 「去支付」→ 扫码页 → 点击任意处 → 成功页 →（1.5s）→ 首页。
- **倒计时**：1Hz 递减；≤30s 变红；归零进入超时态。
- **成功环动画**：`pop` 关键帧 `scale .4→1.08→1` + opacity 0→1，0.5s `cubic-bezier(.2,.9,.3,1.2)`。
- **入场过渡**：⚠️ 设计里曾用 opacity 进场动画，但**已移除**——切勿让任何内容以 `opacity:0` 起始再靠动画显形（车机后台/降级时动画可能被节流，导致内容永久不可见）。内容默认即可见，动画只做锦上添花（如 transform）。

## State Management
建议状态（Compose `remember`/ViewModel）：
- `screen`: 枚举 `Home | Category | Detail | Confirm | Pay | Success | Orders`（外加覆盖层开关 `netError`）。
- `currentCategoryKey`: 当前分类。
- `activeNav`: 当前高亮导航项（与 screen 解耦，详情/确认时保持来源）。
- `selectedProductId`: 详情/确认/支付的目标商品。
- `heroIndex`: 当前 Banner 张数（3s 定时器驱动）。
- `detailThumbIndex`: 详情主图索引。
- `payRemainSec`: 倒计时秒数（初始 179 = 02:59）。
- `orders: List<Order>`: 订单列表（初始 = seed 3 笔；支付成功 `prepend` 一笔，时间取当前 `yyyy-MM-dd HH:mm`）。
- 可选配置：`fsScale`(默认 1.24)、`accent`(默认 #2FD6C4)、`heroLayout`(默认 A)、`slideSpeedSec`(默认 3)。

数据无需后端：全部来自本地静态表（见 `design_src/data.js`，可直接翻成 Kotlin `data class` + 常量表）。`¥` 金额格式 `"%.2f"`。
