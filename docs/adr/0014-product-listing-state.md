# ADR-0014 · 商品上架状态:引入 is_active + 下架=隐藏 + 删除降级为受限

- **状态**:Accepted(2026-06-04)
- **范围**:共识 §1 后台「商品管理」+ §3 产品决策(新增「商品上架状态」行);跨 catalog-browsing / ordering / admin-console / car-browsing / car-checkout 五能力。
- **触发**:用户实测两个问题——① 后端删掉的商品,车机下单链路体验异常(详情进无返回出口的「商品已下架」死页,且下单接口对商品存在/在架零校验、能静默下单成功);② 缺真正的「下架」能力(products 无状态字段)。
- **实现**:OpenSpec change `product-delisting-and-purchase-guard`(技术细节见其 design.md)。

## 背景

`products` 原本没有上架状态(只有分类有 `is_active`)。后台只能硬删商品;`order_service.place_order` 只跑纯输入校验,不查商品是否存在/在架,直接用车机快照落单——已删商品因此能"静默下单成功"。详情接口对查不到的商品返回 404「商品已下架」,但那只是"查不到"的文案,不是真状态;车机 `DetailUnavailable` 态此前还是无返回按钮的死页。

## 决策(用户 2026-06-04 明文拍板)

1. **引入商品 `is_active`**(默认 1=上架)。老库启动幂等迁移加列,存量全部在架,零干预。
2. **下架 = 对顾客彻底隐藏**:下架商品不进推荐 / 分类列表 / banner;详情接口对下架商品按 404「商品已下架」返回。可逆(上架恢复)。
3. **下单拦截不可用商品**:下单逐件校验商品存在且在架,任一不可用 → 整单拒绝,返回 409「商品已下架」(列出不可用项)。**不改价格快照规则**(仍用快照价,不重取现价)。车机收到 409 → 明确提示 + 移出购物车 + 退回购物车,不静默成功、不进死页。
4. **删除降级为受限**:后台日常下线走「下架」;「永久删除」仅对**从未被任何订单引用**的商品开放,被引用的禁删并提示改用下架。**这覆盖了上一轮的 D8(删商品即置空订单行引用)**——现在被订单引用过的商品根本不让硬删,历史快照与可逆性更稳。

## 备选与取舍

- **下架表现**:置灰可见 vs 彻底隐藏 → 选**彻底隐藏**(更接近真实电商,顾客不会看到不可买的东西)。
- **不可用下单的状态码**:404 vs 409 → 选 **409**(语义=与当前商品状态冲突,车机据此与"网络异常"分流)。
- **可用性判定落点**:抽纯规则 `rules.ordering.unavailable_items`(100% 单测)+ service 查库,保持 `rules` 纯函数闸门。

## 后果

- 顾客侧只读接口与下单都尊重 `is_active`;后台仍能看到并管理下架商品。
- 上一轮 D8 的「删除即置空引用」行为被本 ADR 取代;相关测试已改写为「被订单引用→禁删、改下架」。
- 迁移随后端部署自动跑(加列默认在架);回滚=代码回退,列保留无害。需重出车机 release 包。
- 不做:库存扣减/售罄、缺货登记(仍范围外)。
