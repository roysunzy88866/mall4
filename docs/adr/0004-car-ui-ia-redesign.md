# ADR-0004 · 车机端 UI / 信息架构原型定稿

- **Status**: Accepted
- **Date**: 2026-05-29
- **Amended**: 2026-05-29(同日追加「设计稿对照表」小节,Claude Design hi-fi 稿验收 + 3 处不一致裁决);2026-05-30(幻灯张数「4 张」→「3–5 张(典型 4)」,由 [ADR-0005](0005-banner-recommendation.md) 修订)
- **Tags**: product, car-ui, ia, consensus-change, design-handoff

## 背景 Context

初版共识([需求共识.md](../../需求共识.md) v2026-05-28)对车机端只给了粗线条:1920×720、首页「轮播 Banner + 分类网格」、详情页、下单弹码。视觉与具体信息架构(IA)留待设计稿(共识 §6 A4)。

2026-05-29 与用户做了一轮**低保真原型共创**(ASCII 线框,见 [prototype-wireframes.md](../prototype-wireframes.md)),边画边定。过程中用户对车机端 IA 做了多处调整,**超出初版共识若干锁定项**,需走「共识修改流程」并记录本 ADR。

## Decision

车机端 UI/IA 重新定稿如下(均经用户明文确认):

1. **屏幕比例**:1920×720 → **1920×1080(16:9)**
2. **导航**:改为**左侧常驻导航** —— 推荐 / 车载用品 / 加油充电 / 户外旅行 / 3C数码 / 品质生活 /(最底)订单
3. **品类**:由「车载用品 + 电子配件」**扩充为 5 大分类**(同上);**分类即导航,取消独立分类页**,点分类直接出该类商品网格
4. **推荐页**(原「首页」改名):顶部单张大图**自动幻灯 4 张、3 秒切**(原 4 秒);下方「为你推荐」商品网格(每行 2 个,约 10 个,原为分类网格)
5. **详情页**:左 主图 + **最多 3 张缩略图**(不足按实际 1~3 张自适应,见下「补充澄清 §2」);右 名称 / 价格 / **固定信息(7天无理由·包邮·自营)** / 描述 / 下单
6. **下单流程**:详情「下单」→ 新增**确认订单页**(含**固定假收货信息**「只展示不录入」+ 订单详情 + 「去支付」)→ 全屏二维码 + **3 分钟倒计时** → 点屏任意处 = 支付成功(保持 F5)→ 「支付成功」1.5s 回推荐页;倒计时归零弹「支付超时」提示但**系统不处理**
7. **订单页**:车机端**新增订单历史页**(原共识订单仅后台可见)
8. **订单价格**:下单是「拍照」动作,订单永久显示**下单时的价格快照**

## 对初版共识的影响(变更项)

| 初版共识 | 调整为 | 性质 |
|---|---|---|
| F2 屏幕 1920×720 | 1920×1080 | 改值 |
| §1 首页轮播 + 分类网格 | 推荐页:幻灯 + 为你推荐网格;分类移入左导航 | 重构 |
| F3 品类 车载用品+电子配件 | 5 大分类(含户外旅行/品质生活) | 扩范围 |
| F4b 轮播 4 秒 | 3 秒 | 改值 |
| §2 排除「收货地址录入」 | 确认页显示固定假收货信息(只展示不录入) | 放宽 |
| F5 下单→直接弹码 | 下单→确认页→弹码(+倒计时) | 增步骤 |
| (无)车机端订单历史 | 新增订单页 | 加功能 |

## Rationale

- 用户为车机大屏(16:9)重新设计,左侧常驻导航在宽屏上利用率高、切换分类快
- 确认页 + 收货信息让 demo 更接近真实电商体感(虽仍假支付),对老板/同事演示更有说服力
- 倒计时 + 「支付超时」纯演示化:核心「点屏=成功」机制不变,超时不处理以免演示中被动中断
- 价格快照符合电商常识:历史订单不应随商品改价而变

## Alternatives Considered

- **A: 维持初版(1920×720 + 顶部 Banner + 底部分类网格 + 下单直接弹码)** → 用户认为不贴合其设想的大屏电商体验,主动要求改
- **B: 分类做成独立页(顶部 tab 或单独页面)** → 用户选择「分类即左导航」,大屏下更直接,省一次跳转
- **C: 支付用倒计时自动成功 / 「我已支付」按钮** → 用户选择保持共识「点屏任意处=成功」,倒计时仅作装饰

## Consequences

- ✅ 车机端 IA 明确,可据 [prototype-wireframes.md](../prototype-wireframes.md) 进入视觉设计 / 实现
- ✅ 需求场景([user-stories.md](../user-stories.md) US-CAR-01~07)已据此填实
- ⚠️ 切片范围相应增大:新增「车机端订单历史」「确认订单页」,C8~C10 工作量上升
- ⚠️ 低保真线框有保质期,设计稿出现后须归档,避免成为第二真相源
- 📎 关联:[需求共识.md](../../需求共识.md) §1/§2/§3 + [story-map.md](../story-map.md)(新增 US-CAR-07)

## 补充澄清(2026-05-29 同日,审计 user-stories 后)

回填车机端 Gherkin 时发现三处"前端有、后端/规则没定"的缝,经用户明文拍板补齐:

1. **「为你推荐」数据来源** = **全部商品**(随机或按上架序),后台**不单独管理**(区别于"推荐位"那 4 张幻灯,推荐位仍由后台挑)。→ 共识 §1 推荐页。
2. **商品图不足 3 张** → 详情页**有几张显示几张(1~3 自适应)**,后台**不强制**必传 3 张。→ 共识 §1 详情页 / §7。
3. **价格快照时刻** = **点「下单」进确认页那刻锁定**(确认页上的"去支付 ¥X"即进订单的价;此后改价不影响该单)。→ 共识 A8。

### C. 视觉决策锁定(由设计稿替共识 §6 #1 / A4 收口)

设计稿即共识 §6 "视觉设计稿"的交付物,以下视觉决策**就此锁定**:

- **主题**:深色冷调(bg `#0A0C0F`),青色强调(accent `#2FD6C4`)
- **字号密度**:**特大 = 基准 × 1.24**(`fsScale = 1.24`,可作运行时配置但默认锁此)
- **字体**:中文 Noto Sans SC;数字/品牌 Oxanium;打包进 `assets/fonts`
- **Banner 布局**:布局 A(宽幅横幅,左侧渐变文字)
- **导航 7 项顺序**:推荐 / 车载用品 / 加油充电 / 户外旅行 / 3C数码 / 品质生活 / 订单(固定)
- **3 固定标签文案**:`7天无理由` / `包邮` / `自营`(固定胶囊,青字勾,与共识 §1 详情页一致)
- **订单 seed**:初始 3 笔(支付成功 prepend),符合共识 A3"demo 数据自动 seed,大致即可"
- **占位形态**:商品图/Banner 图为 135° 条纹占位(由 seed 阶段或后台上传替换为真实图)

### D. 设计参考源的边界
