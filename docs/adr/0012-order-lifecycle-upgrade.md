# ADR-0012 · 订单全生命周期升级(购物车 / 物流 / 退换货)

- **Status**: Accepted
- **Date**: 2026-06-03
- **Tags**: scope, product, consensus, governance

## 背景 Context

第一刀(`car-storefront-browse`,车机浏览主干)归档后,用户提出三块新需求,逐一**反转了 `需求共识.md §2` 已锁定的「明确不做」项**:

| 新需求 | 共识 §2 原状 |
|---|---|
| 购物车 + 批量下单 + 多商品订单 | ❌「购物车 · 用户明确排除」 |
| 物流信息(订单页看,后台打通,Mock) | ❌「物流/配送/**订单状态流转** · 用户明确排除」 |
| 取消订单 + 7 天无理由退货 | ❌ 范围外(订单状态恒「已支付」) |

这把产品定位从「**极简单品下单 demo**」升级为「**订单全生命周期 demo**」。三块需求共用一个新底座——**订单状态机**(订单从「死记录」变成有生命周期的「活订单」)。按 CLAUDE.md「共识防漂移」,范围反转须走「用户明文 + 改共识 + 记 ADR + 同提交」,本 ADR 即该裁决记录。

## 决策 Decision

2026-06-03 经用户多轮 AskUserQuestion 逐项拍板,纳入以下范围与边界(锚点见 `需求共识.md §3`):

1. **购物车 = 车机本地临时态**(F11):关 app / 下单后清空,**不落后端**(无新表/接口);上限 **20 种商品 × 每种 99 件**;车机右上角购物车图标 + 数量角标入口。
2. **下单交互**(A11):详情页 = 「加入购物车」+「立即购买」(单件直下单跳过购物车);购物车每项带勾选框(**默认全选**),只结算勾中项,批量下单。
3. **多商品订单**(A10):一单多行多数量(后端订单模型本就支持多行);价格快照仍在「进确认页」那刻锁定整单(沿用共识 A8)。
4. **订单状态机**(F12):`待发货 → 已发货·运输中 → 派送中 → 已签收`;后端按**可配间隔自动推进**(mock),后台可**一键快进 / 手动改状态**(演示用)。
5. **物流**(F13):跟状态走的 **mock 轨迹时间线**(已揽收→运输中→派送中→已签收),订单/详情页展示;不接真实物流 API,「跟后台打通」= 数据由服务器提供、非车机写死。
6. **取消订单**(F14):**签收前**(待发货/在途)用户可撤单 → **自动生效**(不审核)、mock 退款、物流 mock 转「已拦截/退回」;订单转「已取消」。
7. **无理由退货**(F15):**签收后 7 天内**、**整单退**、走**后台审核**(申请→退货审核中→后台通过→已退款 / 后台拒绝→退货被拒;`退货中`为预留态,demo 单步退款,见 cancel-and-return design.md R3);退款为 mock(订单显示「已退款 ¥xx」);申请时填退货原因(下拉:7天无理由/质量问题/拍错了…)+ 选填说明。7 天期限**可配时长** + 后台**一键快进到过期**(现场能演完整周期,同第一刀倒计时 179 秒的 demo 化思路)。
8. **换货 不做**(A12):本批明确排除;真要做后续单开一刀。
9. **后台扩展**:订单状态管理 / 快进、退货审核 UI;**营业额 = 扣除已退款/已取消后的已支付订单合计**(A13,避免数字虚高)。
10. **库存**沿用共识:仅展示、不拦截下单。

## 理由 Rationale

- 用户明确要把 demo 做成接近真实电商的全流程,且在多处选了**更完整的版本**(退货带后台审核、购物车可勾选、详情留立即购买),取向是「贴真实」而非「最省」。
- **购物车放本地**:购物车是「未下单的临时挑选」,放车机本地态最简、零后端改动;真实电商的跨端同步对 demo 过重(共识「车机不缓存业务数据」对**临时购物车**这一未提交态破例,不影响「已下单数据只存服务器」)。
- **状态自动 mock + 后台可干预**:演示时不必人工一步步点也能看到全流程,后台又能现场快进/纠正,最省心。
- **7 天可配 + 快进**:真 7 天无法现场演完;可配 + 后台快进让「可退 → 过期不可退」当场走通。
- **取消自动 / 退货审核**:取消发生在签收前(货未到/在途),拦下即可、无需审核;退货发生在签收后,审核态更贴真实且给后台一块可演示的操作。
- **整单退(非按件)**:按件退会让订单状态机炸开(部分退/部分留),对 demo 收益低、复杂度高。

## 替代方案 Alternatives Considered

- 购物车:**后端持久化**(新表+接口,跨端在)→ 否,demo 过重。
- 订单状态:**后台纯手动推进** → 否(演示要人工逐步点);选自动 mock + 后台可干预。
- 退换深度:**极简自动生效(无审核)** → 否,用户要审核态。
- 7 天计时:**按真实 7 天** → 否(现场演不完);选可配 + 快进。
- 退货粒度:**可按件退** → 否(状态机复杂);选整单退。
- 购买入口:**只走购物车**(详情页只有加购物车)→ 否;保留立即购买。
- 结算:**整车一起下单**(无勾选)→ 否;选可勾选(默认全选)。

## 后果 Consequences

- ✅ 范围与边界清晰、可测;三块共用订单状态机底座,分三刀实现(依赖顺序见下)。
- ⚠️ **工作量约 3 刀**,每刀都不小;后台 `admin-console` 能力相应扩展(状态/快进/退货审核)。
- ⚠️ **后端 `ordering` 能力扩展**:订单新增「状态 / 物流轨迹 / 退货单」;`后端需求.md`「订单状态恒『已支付』」「物流不做」**被本 ADR 取代**(该文件相应行加指针)。
- ⚠️ **新增锚点 F11–F15 / A10–A13**(`需求共识.md §3`);改锚点后完工前须 grep 锚点值 + 通读找矛盾。
- 📎 切刀草案(依赖顺序):
  - **第二刀(重定义)**`cart-checkout`:购物车 + 多商品下单闭环(详情→加购物车/立即买→购物车勾选→批量下单→确认→扫码支付→多商品订单 + 订单历史)。
  - **第三刀** `order-lifecycle-logistics`:订单状态机 + mock 物流(自动推进 + 后台快进/改 + 订单/详情看物流时间线)。
  - **第四刀** `cancel-and-return`:取消(签收前自动)+ 7 天无理由退货(签收后、整单、后台审核、可配快进)。
